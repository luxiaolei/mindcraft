# 安全、隐私、许可与运营边界

## Minecraft 与开源
Mindcraft 采用 MIT 许可证；保留上游 LICENSE、署名和 fork 关系。Minecraft Java 游戏本体、名称和资源不属于本项目开源内容，孩子需要合法客户端。部署 Minecraft 服务端必须阅读并接受官方 EULA： https://www.minecraft.net/en-us/eula 。商业化、服务器服务、品牌展示必须另行评估官方 Usage Guidelines： https://www.minecraft.net/en-us/usage-guidelines 。

## 本地演示与正式环境的重大区别
- **仅本地演示**：Paper/Minecraft 服务端 ONLINE_MODE=FALSE 是为了让不持证的机器人调试；由于没有微软账号身份认证，所有端口必须仅绑定 localhost 并经 SSH 隧道访问。绝对不能把这种模式公开到互联网或不受信任的局域网。
- **正式多人环境**：ONLINE_MODE=TRUE、独立授权的 Minecraft 机器人登录身份、账户/世界隔离、反骚扰和家长授权。不能以本地测试成功推断许可合规。
- **AI 控制**：Mindcraft 默认可能有高权限游戏动作；在 PoC 的 blocked_actions 列表里禁用任意代码(!newAction)、攻击、改游戏模式等。请在真实 Docker 运行中复核，不仅检查字符串。
- **密钥**：keys.json 必须被 .gitignore 忽略；不能上传 GitHub、日志、聊天记录。API 提供商经家长/产品方明确核准后才接入。
- **儿童**：设计为有限任务的学习伙伴，避免拟人化情感依赖、无限聊天或操纵性奖励。儿童隐私、监护人同意、适用年龄及美国 COPPA / 英欧当地法律应在目标市场正式上线前请专业人员审核。
- **语音**：PoC 第一期无麦克风收集。以后必须有明确录音指示、主动关闭、保留与删除策略、服务商数据处理核查，默认不保存原始音频。
- **屏幕**：机器人邻近方块感知与孩子屏幕画面完全不同。任何屏幕共享都需要用户主动授权且能随时撤回，不能暗中截图。
- **多人**：不同玩家 UUID 的游戏事件不准交叉进入学习者记录；AI 只对明确绑定的教学对象进行语言引导。
- **网络**：初期端口 25565、8080 仅绑定本机；不要把 MBP 当作公开服务端暴露。Docker 管理端口严禁公网开放。

## 禁止称作已验证的能力
现有 README 提到的 speak 只是 Mindcraft 的语音合成配置，无法推导为“支持全双工低延迟英语”。上游 allow_vision 是机器人视角，**不是孩子的画面**。现阶段没有验证个人信息合规、教学有效性、商业平台授权和全天在线稳定性。

## 出现这些情况必须停止测试
无法确认玩家是授权参与者、Docker 将未认证服务器对公网开放、密钥写入版本库、AI 使用任意代码动作、模型对孩子发出有害指令、可重现越权访问他人学习记录。此时优先停止联网与收集，再修复问题。
