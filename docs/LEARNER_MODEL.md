# 儿童学习者模型与个性化教学（规划）

设计原则：**过去经验 + 喜好 + 可追溯行为证据 → 暂时教学判断 → 下个任务 → 新证据**。不将儿童固定分类，不把 ASR 误听视为发音错误。PoC 当前不采集真实儿童长期档案。

## 1. 独立模型与数据最小化
- LearnerProfile：随机化 learner_id、家长认可的英语水平偏好、感兴趣的游戏主题、每次最大使用时长；不需要真实姓名、生日、面部视频。
- Session：session_id、授权玩家 UUID、当前任务、开始结束时间、同意状态、模型用量。
- Observation：event_id（由游戏事件采集）、actor_id、task_id、skill_id、首次/重试标记、帮助程度、完成状态、来源。
- SkillHypothesis：skill_id、证据集合、状态（待观察/有进步证据/在帮助下完成/跨场景独立证据）、最近复核时间；永不称“该孩子不会英语”。
- TeachingPlan：当前任务、英语难度、可接受提示、参考的 evidence_id 和为什么这样推荐。
- FamilyControls：家长可查看/修订/撤回兴趣和观察；撤回后重算，不将已删除证据再次读入模型。

## 2. 证据的四条纪律
1. **孩子行为 != AI 行为**。只能把 actor_id 为受管孩子且事件可信的操作算作其成绩。
2. **首次独立 != 提示后成功**。有提示则仅说明“在帮助下完成”；不能包装为独立掌握。
3. **重复操作不是独立样本**。同一任务/场景的重复点击和尝试单独保留，但跨场景评估只计独立任务上下文。
4. **推断需保留不确定性**。一次失败可能是游戏操作、网络、阅读、ASR、任务不适合；不要跨领域诊断。

## 3. 两个英语等级举例
- Starter：“Wood!” 可作为有效请求；AI 回应一个自然简短句：“Let's find wood.” 不要求背诵纠错。
- Builder：AI 引导完整协作：“We need three logs. Can you find an oak tree?” 孩子可以协商计划、问为什么。
- Advanced：鼓励解释策略、提出假设、反思结果；同时满足时长限制。

## 4. 决策节奏
每 1–3 个关键游戏动作/任务检查点生成一个简短教学机会，而不是每个点击都插话。优先给自主探索时间；孩子主动求助才逐步给提示。完成后邀请孩子用英语讲一件自己做过的事，而不是自动颁发“掌握”标签。

## 5. 最小化接口（拟实现）
- POST /sessions：家长授权后创建会话。
- POST /events：服务端提交带签名、去重 ID、玩家归属的事件。
- GET /learners/{id}/summary：只返回可解释状态及证据。
- POST /learners/{id}/corrections：家长修正/撤回。
- DELETE /learners/{id}：覆盖原始记录、索引、缓存及服务商数据请求流程。

这些接口当前**尚未实现**，不应理解为现有服务。
