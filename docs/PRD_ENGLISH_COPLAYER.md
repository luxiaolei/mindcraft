# AI English Co-Player — 产品需求文档（PoC v0.1）

状态：设计与基建阶段；**不是已上线产品**。更新：2026-11-11。基于 [Mindcraft](https://github.com/mindcraft-bots/mindcraft) 的独立 fork，不属于 Mojang/Microsoft 官方产品。

## 1. 定位与用户
国际 Minecraft Java Edition 家庭市场的「在游戏中真实协作的英语 AI 同伴」。孩子在正版客户端进入私有多人服务器，AI 以另一个 Minecraft 玩家身份出现，以英语协作完成游戏目标。首发技术演示面向家长陪同；暂不销售、不得当作未经验证的教育诊断。

**价值假设**：相较纯英语聊天，AI 看到游戏事件并参与完成目标，会增加孩子主动表达英语的次数、自然交流意愿和任务参与度。需通过真实用户验证，不是既成事实。

## 2. 最小用户旅程
1. 家长启动 MBP 本地 Compose，孩子用正版 Minecraft Java 加入受限私服；AI Buddy 作为另一个玩家加入。
2. 孩子说或输入 “Can you help me find wood?”；Buddy 根据可观测方块/位置解释，并通过被允许的 Minecraft 命令带路。不能看到的状态明确说不知道。
3. 孩子自己收集木头、准备搭小屋；Buddy 用简短英语做下一步引导。孩子请求提示后，先给口头线索，再示范，最后才考虑代做非核心步骤。
4. 游戏事件成为教学证据；新任务必须由孩子完成关键动作，不能因 AI 代做就记录为孩子掌握。
5. 家长可以结束会话；长期档案在 PoC **尚未实现**，将来按单个家庭同意、访问、纠错、删除。

## 4. 多人设计
Minecraft 服务器本身支持多人。PoC 一房间限「1 名测试玩家 + 1 个 AI」以控制变量；后续支持家长在场、朋友加入及“一家庭一世界/一机器人”的逻辑隔离。多人时 AI 必须区分哪位玩家是教学对象，并且不能私聊/记录未授权玩家数据。

## 5. 英语教学与个性化
依据家长提供的英语水平（初学/基础/进阶）、兴趣、既往任务与**有证据的尝试结果**调整措辞。记录“独立完成”“提示后完成”“未完成/未知”，不从单次识别失败推断知识缺口。错误识别不能把游戏误点、ASR 误听视为语言能力证据。让孩子先尝试，不把作品代做。

**交互示例**
- Child: “Wood!”
- Buddy: “Yes, wood. I see an oak tree. Follow me!”
- Child: “How do I make planks?”
- Buddy: “Open your crafting menu. Try putting one log in. What happened?”

## 6. 明确不做
MVP 不开发 Minecraft 本体、不训练基础模型、不依赖 Vivix、不做摄像头人脸采集、不做自动情感依赖陪伴、不做成绩/学习能力诊断、不收集儿童真实姓名、不自动公开服务器、不把商业发行授权当作已解决。

## 7. 产品北极星与失败条件
北极星候选：每次会话中「孩子主动英语表达且与游戏行动相关」的有效回合数。另监测引导任务完成率、AI 误报游戏状态比例、独立操作比例、延迟、家长满意度、每会话成本和停止请求成功率。低于任务/安全门槛不对儿童开放试点。
